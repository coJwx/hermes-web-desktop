# 黑盒验收计划（服务器不修改）

状态：客户端自动化与隔离页面部分已执行，逐项范围见 evidence/client-verification.md。远程/native及固定设备性能未执行。OpenSpec validate只能验证工件，不能证明远程服务器支持并行附着。

## 环境与范围

- 固定现有远程服务器和实际部署版本，不部署新Python代码、不改配置或生成协议；正常使用已有会话RPC。
- web/src/test中可控wire fixture模拟已有create/resume/activate/events.since、事件和请求；复用真正共享客户端/channel，不让fixture提供产品所需的新API。
- 已有测试profile可用于远端A→B→A；若部署没有可用测试profile，不新建服务器配置，fixture覆盖并明确标注远端未验证。
- X/Y两个客户端查看同一会话；网页工作区A/B/C三个会话；Rust透明桥和浏览器直连分别记录。
- 故障注入由web测试网络fixture控制，可暂停已有RPC回复、丢ACK、断WS、重排live/replay、截断ring或改变epoch。
- 记录构建SHA、视口/硬件、逻辑连接数、已有RPC轨迹、实际应用缓存/timer/URL计数与browser heap峰值；不记录秘密或原始用户正文。

## 性能与完成标准

生产构建固定设备上B01可见p95目标<100ms；不是已测结论，不做脆弱毫秒级单元断言。记录warm切换、并行输出CPU/heap、全量冷恢复瞬时heap和16关联上限。应用保留数据可以有预算，但server响应峰值及后端Agent内存不能由客户端保证。

完成条件是两份客户端spec有匹配行为证据；支持目标必须实际证明同WS两会话同时事件/请求不丢绑定。web之外无修改、无服务器部署/配置步骤、无新生成协议。真实远端/原生环境未执行时列为未验证；wire fixture全绿不自动等于部署可用。

不覆盖：服务器原子snapshot/解绑、远程Agent容量、完整历史分页、跨窗口单WS、所有工业聊天应用的一致架构、模型质量或全协议exactly-once保证。
