## Why

当前网页页签切换会断开旧 WS 并重新恢复目标会话，造成切换等待和后台状态不可见。采用方案 4，在一个持续连接上维护多个会话的独立状态，缓存有效的切换只改变视图。

**范围已于 2026-10-13 修订：只能修改 web/ 内的前端、Rust、测试和文档；远程后端不可修改。** 用户已授权实施；客户端实现落在 web/，真实远程/原生验收仍待执行。先前需要服务端扩展的版本已被本方案替代。

## What Changes

- 分离工作区连接、独立会话状态和活动视图，使用现有 /api/ws 与 JSON-RPC 方法，不新增服务器接口或字段。
- 按运行会话 ID 路由实时事件和 approval/clarify/sudo/secret 请求，后台会话保持可达的状态和请求入口。
- 缓存命中的切换不重连、不重复附着；重连使用现有 activate/resume/events.since，按运行 ID、epoch 和投影可信度分开恢复。
- 关闭页签释放显示缓存与不需要的媒体资源；无服务端单会话解绑能力时保留本连接范围内的有限轻量登记，不能声称服务器绑定立即释放。
- 运行/等待会话即使关闭页签也有可见后台入口；停止任务保持显式操作，不以 session.close 模拟取消订阅。
- 冷恢复/截断期间不假设现有快照有原子事件游标；运行中采用权威快照替换显示，终态再次校准，避免把边界不明的 delta 盲目拼接。
- 完整历史、文本/图片草稿和事件缓冲按前端预算管理；实际服务器全量 RPC 解码峰值和后端资源无法由前端预算保证。
- 功能不支持的远程服务器显式使用当前兼容模式，不要求升级服务器，也不静默创建每页签 WS。

- 2026-10-14追加授权：工作区提升到profile作用域的路由父级；访问Files/Logs保留WS、页签和有限数据/草稿，仅卸载聊天视图并暂停视图轮询。刷新仅按scoped存储的会话ID、顺序和活动项冷恢复，路由形式不变。

## Capabilities

### New Capabilities

- `web-chat-multiplexing`：单连接工作区、会话隔离、后台状态、快速切换、草稿和资源生命周期。
- `web-chat-existing-protocol`：仅使用现有远程接口的附着、补发、保守恢复、连接回收与兼容策略；要求作用于 Web 客户端，不能转化为服务端开发任务。

### Modified Capabilities

无。已有桌面变更保持独立；旧的 gateway-session-subscriptions 设计规范已移除，不再作为实施依赖。

## Impact

- **允许修改**：web/src、web/src/test、web 内 Vitest、README.web-chat.md、web/openspec；Rust 如有必要只能修改 web/src-tauri 中现有生命周期适配。
- **只读依赖**：apps/shared 已有 JSON-RPC/WS 客户端与类型；通过 web/src/lib/gatewayClient.ts 传递现有 replay=false 选项，不修改共享包源文件。
- **禁止修改**：tui_gateway、hermes_cli 服务端、apps/desktop、apps/shared、服务器配置和生成协议文件；不运行协议生成来引入新方法。
- Rust 默认无需为此功能修改；已有 WS 隧道继续透明转发，不加入会话调度、假的解绑 ACK 或代理 RPC。
- 无新运行时依赖、服务器历史迁移、秘密持久化、模型核心工具或非秘密配置环境变量。
- 风险关注点是前端异步恢复、请求归属、草稿和资源释放；严格验证这些边界，但不改变公共服务器协议。
